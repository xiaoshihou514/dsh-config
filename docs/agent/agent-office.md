# 智能体办公室

Agent Teams 的 3D 可视化，以「办公室模式」呈现：侧边栏左下角「办公室」开启（唯一入口），办公室里「← 返回对话界面」关闭；开关、正在看的团队、对话栏宽度存在 localStorage（`dsh-config:office`），刷新后直接回到办公室。

办公室挂在 `shell.overlay`，默认铺满窗口：左栏是组长动态（当前动作、待办进度、最近派活）/ 队伍卡片 / 成员详情，中间 3D 场景（组长头顶不冒气泡），顶部 HUD。点成员的「打开对话」切换当前会话，覆盖层收成左侧成员栏、3D 场景隐藏，右边是原生对话（原生中央列靠左内边距让出成员栏）；Esc 或「回到办公室」收起对话。项目显示名用文件夹对应工作区的标题（项目面板里 ✎ 改名，原生侧边栏同步），没有时用文件夹名，3D 墙上的招牌跟着变。顶栏「项目」面板：已有团队（每个文件夹一个，取最近组建的那个；同一文件夹重新组队后，记住的旧团队自动换成新团队，新团队在招到第一个成员后出现；记住的组长会话被删除时连续 3 次找不到就忘掉，回到默认选择）与「组建新团队」——列出还没有团队的工作区或「选择其他文件夹…」，点击后在该文件夹新开会话并发送项目经理提示词（`TEAM_PROMPT`）。界面全部自绘（无原生 select），沿用原生 `--dsw-*` 配色，带游戏 HUD 风格。

## 结构

| 文件 | 职责 |
|---|---|
| `src/agent-office.ts` | 宿主插件：`GET /dsh-config/office?lead=`（需 `x-dsh-config: agent-office`，带 ETag）、`POST /dsh-config/office/override`（手动指定岗位 / 人设 / 档位，存 `$DSH_HOME/dsh-config/office-overrides.json`）、`GET /dsh-config/office/teams`（组建过团队的会话列表，按最近活跃排序）、`GET /dsh-config/office/solo?ids=`（共享办公室入选者的详情）、`GET /dsh-config/office/leads?ids=`（老板办公室组长的判定事实）、`GET /dsh-config/office/scene.js`（ETag 协商缓存） |
| `src/office/derive.ts` | 纯推导：会话事件 → 成员活动、当前动作、交流、任务（有单测） |
| `src/office/boss.ts` | 老板办公室：组长「汇报 / 出错 / 等组员」的判定（宿主与浏览器共用） |
| `src/office/classify.ts` | 模型 → 厂商 / 档位，名字 + 描述 → 岗位；改档位规则看 `FAST_PATTERNS` / `FLAGSHIP_PATTERNS` |
| `src/office-scene/` | three.js 场景（独立 ESM `lib/office-scene.js`，进入办公室时才加载）；`slack.ts` 是空闲角色的摸鱼动作 |
| `src/client/office/` | 办公室模式：`OfficeShell.tsx`（覆盖层、HUD、项目面板、队伍 / 详情 / 交流）、`store.ts`（持久状态）、`styles.ts`（样式）；`SessionAvatar.tsx` 是对话界面的角色头像 |

## 概念模型：单位与子代理

- 可视化的单位只有三种：组长、组员（在组长 `team/member` 名册里，`/office/teams` 返回 `memberIds`）、单智能体（顶层独立会话）。组员技术上也是派生的子会话，但不算子代理。
- 子代理 = 不在名册里的 subagent 会话（组长、组员、单智能体用工具临时派的，任意层级）。子代理不单独出现：不占编队格子、不入座、不去老板办公室汇报。
- 子代理在跑 = 派它的单位在跑（`projects.ts` 的 `unitOf` 沿子代理链往上找最近的单位，`busyUnits`）。办公室把它并进在跑判定（`useBusyUnits` 合进 `live`）：场景动作、老板办公室判定（组长 / 单智能体的子代理还在跑就不算这一轮结束）、项目忙闲都按这个口径。

## 项目切换器 = 势力面板

- 统一的游戏风小部件（`client/office/squad.tsx`，与 HUD 徽标同一套渐变方块 + 底部压边 + 像素画）：`Squad` 编队——一个 7×8 像素小人一个单位，组长戴金冠排第一，在跑的亮绿、轻微跳动，空闲的灰暗，超过 8 个标「+N」；`Seal` 状态徽章——干活中是绿色方块里跳动的像素柱，休整是灰色方块里的月牙；`Tally` 计数徽章（徽章 + 数字）。数字与路径都在悬停提示里，界面文字压到最少。
- 触发按钮：项目名 + 两枚计数徽章（干活中几个项目 / 休整几个项目）。
- 面板：金色抬头牌「项目」+ 两枚计数徽章；每个项目是一张势力卡——徽标方块、名字、下面一排编队、右侧状态徽章（团队另附最近活跃时间），在跑的卡片左缘亮绿。顺序：共享办公室（单人团队，编队是全部在座单智能体，点了切过去）→ 团队（在跑的在前）→ 单智能体（按文件夹，点了去共享办公室并选中）→ 组建新团队。
- 数据（`projectActivity`，零扫描）：团队 = 组长 + 名册组员；单智能体项目 = 共享办公室入选者按 `cwd` 分组。选择器只返回结果 JSON，会话列表其他变化不触发重渲染。

## 共享办公室（单智能体）

- 入口：HUD 页签「办公室 / 共享办公室 / 角色图鉴」。所有项目的单智能体（非团队会话）坐一个大办公室，与团队办公室并存，切换时场景按新布局重建。
- 入选（`client/office/shared.ts` 的 `pickSolo`，浏览器端，零扫描）：原生会话列表（`useSessions`）里的顶层会话（`rootOf` 等于自己，即不是任何会话派出的子代理；普通分叉算独立会话）、非空白、不是组长（以 `/office/teams` 团队列表为准，含 `replaces`）；并且正在运行或 24 小时内有活动（`updatedAt`，秒 / 毫秒都认）。派过子代理的单智能体照样入选，子代理本身不入选（算进它所属项目的忙闲）。刚组建、还没招人的组长名册为空、还不在团队列表里，会先当单智能体出现，招了第一个人后转为团队。在跑的优先，其次按最近活动；最多 24 人，多出的只在 HUD 和左栏提示人数。「24 小时」边界每分钟重算。
- 详情：`GET /dsh-config/office/solo?ids=a,b,…`（最多 40 个）只为入选者补模型、当前动作、最近一轮：逐个走 `digestOf`（已加载读内存、未加载按存储版本缓存摘要），成员由 `derive.ts` 的 `memberFromDigest` 组装（与团队成员同一套厂商 / 档位 / 岗位识别，岗位按会话标题），套用手动指定；带 ETag，浏览器每 3 秒轮询、未变化 304。是否在跑仍以浏览器会话状态为准。
- 场景：`createOfficeScene(…, { layout: "rows" })` 开放式长桌，6 列 × 4 排（`ROW_COLS` / `ROW_ZS`），从后排往前排、从左往右填，人面朝镜头。浏览器按项目名排好成员顺序，同项目坐在一起；人进进出出时优先坐列表位置对应的工位，被占了就坐第一个空位（`Agent.seat`）。在跑的打字 / 阅读，空闲的照常摸鱼、闲逛。名牌「角色名·项目名」（`OfficeMember.project`），副标题是会话标题。醒目提醒与横幅只在团队办公室出现。
- 左栏 `SharedPanel`：按项目分组的卡片，点卡片定位，💬 打开它自己的对话（`openSession(id, id)`）。

## 老板办公室

- 入口：HUD 页签「老板办公室」（待处理数红色角标）；团队办公室的醒目提醒横幅上有「去老板办公室」。各团队组长在有事时来这里向你（老板）汇报；单智能体（共享办公室的入选者）这一轮结束时也来（汇报 / 出错，没有「等组员」）。
- 判定（`office/boss.ts` 的 `bossStateOf`）：waiting = 有组员在跑、组长没在干活（没有未结束的步骤，或卡在等组员的工具上）；report / error = 全队停下、组长这一轮已结束，按成败区分；组长自己在干活、或还没开过一轮的不来。单智能体用 `soloBossOf`：这一轮结束且自己没在跑才来。是否在跑以浏览器会话状态为准（`client/office/boss.ts` 的 `bossOf`），宿主推导兜底。看过的汇报 / 出错（`dsh-config:office-ack` ≥ 这一轮结束时间）离开老板办公室；排序：待处理在前、等得最久的先排（先来先办），等组员的在后。
- 候选（`pickLeads`，浏览器端，零扫描）：`/office/teams` 里的组长，只留 24 小时内组长整棵子代理树（组员、组员派的子代理……）有活动（或正在运行）的，最近的在前，最多 24 个。
- 事实：`GET /dsh-config/office/leads?ids=…`（最多 24 个）只为候选读组长与组员的摘要（`digestOf`，已加载读内存、未加载按存储版本缓存），返回组长成员、`leadWaiting`、组员 id 与宿主推导的「组员在跑」；不枚举会话。带 ETag，在老板办公室里每 5 秒、其他时候每 15 秒（只为角标）轮询，未变化 304。单智能体复用共享办公室的入选与 `/office/solo`（一直轮询：共享办公室里每 3 秒，其他时候每 15 秒）。
- 场景（`layout: "boss"`）：老板桌（大桌 + 红色老板椅，空着的椅子就是你，头顶「👔 老板（你）」名牌）在后墙中段，身后墙上挂待办屏（汇报 / 出错在前、等组员在后，超过 5 行慢慢滚动）；桌子与墙屏在首帧后空闲时才搭。汇报 / 出错的组长在桌子左前方斜着排队、面朝桌前：汇报的把文件夹递向桌前、边说边欠身，出错的低头垂手；等组员的在右前方空地（3×3，多出的去休息区）抱臂看表、两点间踱步。组长不带工位、不闲逛；状态不变位置不变，变了换到对应区域第一个空位。名牌常显、按状态描边（汇报金、出错红、等组员蓝），单智能体标「单智能体」，文字气泡悬停 / 选中时才出；排队朝镜头方向一个接一个（每位相隔 2.5 米，名牌在画面上阶梯错开），满 5 人另起一列。
- 正在干活（`client/office/boss.ts` 的 `workingProjects`）：有人在跑、又不在屋里的团队（组长已在汇报 / 等组员的不重复列）与有人在跑的单智能体项目，在跑多的在前。忙闲直接复用项目面板的统计（单位口径：组长、组员、单智能体，子代理在跑算派它的单位在跑，`projects.ts`），不新增请求。不往房间里加人（避免拥挤），只在三处呈现：墙屏下半区「🔨 正在干活 N」（组名 + 一个方块一个单位，一行排不下换行，再多标「+N」；上半区待处理缩为 3 行滚动），经 `OfficeSnapshot.working` 传给场景；左栏「正在干活」分组（与项目面板同款势力卡：编队 + 干活中徽章，点团队切到该团队办公室、点单智能体项目去共享办公室）；HUD 统计「在干活 N」。
- 左栏 `BossPanel`：待处理在前、等组员在后，卡片标明「组长 / 单智能体」；💬 打开对话、✓ 知道了，汇报 / 出错都记为已看过、离开老板办公室（与团队办公室的醒目提醒共用 `dsh-config:office-ack`）。角标、墙屏清单都把单智能体算进去。

## 用量 / 设置入口

- HUD 右侧「用量」「设置」，都不离开办公室。图标自绘（`UsageIcon` 柱状图、`SettingsIcon` 齿轮，与 `OfficeIcon` 同一套 16 格 1.3 线宽描边），放在与左上角办公室徽标同款的渐变小方块里（用量青绿、设置蓝灰），按钮用 HUD 的凸起压边样式；全屏按钮也换成同款描边图标。
- 用量：直接用 usage 面板导出的受控 `UsageDialog`（`open` / `onClose`），用 portal 挂到 body，覆盖层收成左侧成员栏时也铺满窗口。
- 设置：与原生侧边栏设置按钮完全一致。原生设置外壳把状态仓库挂在 `sidebar.settings` 槽位的注册选项上（`store.create()` 返回侧边栏用的同一个实例），侧边栏设置按钮、账户菜单里的「设置」、`settings.open` 快捷键都调它的 `actions.open()`；`OfficeShell.tsx` 导出 `nativeSettingsOpener(ctx.slots)`，点击时经 `ctx.slots.entries("sidebar.settings")` 现查该实例并 `open()`，入口注入为 `settingsHost`。弹窗挂在 body、层级 1000，盖在办公室覆盖层（40）之上。拿不到时退出办公室，让你用侧边栏的设置。（早先用 `ctx.shortcuts.invoke` 不成立：公开的 shortcuts 服务没有 `invoke`，它只在内部注册表上；抛错后旧的回退去点页面上第一个 `[aria-haspopup="dialog"][class*="_trigger"]` 按钮——装了账户启动器时侧边栏没有那颗设置按钮，点到的是别的弹窗。）
- 用量弹窗或原生弹窗（`[data-shortcut-modal]`）开着时，Esc 交给弹窗，不收起对话。

## 对话界面角色头像

- `SessionAvatar.tsx`：当前会话所用模型对应厂商的角色头像（像素版，与办公室体素角色同一张正视图），模型切换时实时更新。同一时刻只出现一处（入口 `client/index.ts` 注册）：
  - `conversation.input.overlay` 的 `ComposerAvatar`：已开始的会话，作为独立元素站在消息输入框左侧外沿（48px，间距 12px，不与框重叠），与输入框垂直居中，输入框随草稿变高时跟着重新居中（每 0.7 秒复查）。左侧放不下时站到输入框上方（左对齐），上方紧挨着有停靠条（待办、排队消息）时站到最上面那条停靠条的上方。「放得下」按真正露出来的区域算：左边界取输入框所在列的左沿与办公室覆盖层（对话展开时固定在左侧、盖在原生对话之上）右沿中靠右的那个——办公室里打开对话时原生对话列被挤窄，头像不会躲到覆盖层底下。会话还是空白时不显示。
  - `conversation.hero.brand.mark` 的 `HeroAvatar`：新会话欢迎页标语左侧（40px，替换内置鱼标），跟随输入框模型选择器：选了工作区就有一个空白会话被主视图持有，模型选择器的 `select()` 对空白会话也会调宿主 `selectModel`，写进它的 `modelSelection` 投影，头像随之切换；没选模型或还没有会话时用默认模型（不退回持久化的旧会话选择）。
  - 原先会话标题左侧那处（`conversation.header.leading` 的 `HeaderAvatar`）已撤掉，导出保留为空实现。
- 当前会话：输入框处直接用槽位给的会话 id；欢迎页只看默认模型。
- 模型：会话的 `modelSelection` 投影（`projectionsBySession[id].values.modelSelection.next`）；会话没自选过模型、或欢迎页还没有会话时，用宿主模型目录的全局默认模型（入口注入 `avatarHost.loadDefault`，即 `remote.session.modelCatalog().default`，读一次缓存）；都拿不到时显示兜帽旅人。厂商按 `classify.ts` 的 `vendorOf` 认。鼠标悬停显示「厂商（档位）· 模型名」，默认模型注明「默认模型」。
- 头像素材：`scripts/build-persona-avatars.py` 取 `sprites.generated.ts` 的正视图网格（即 `人设/体素/` 三视图降采样结果，兜帽旅人来自 `assets/personas/other.png`），从头顶裁到脖子（与 3D 角色同一切分），水平以 `FACE_SPEC` 的两眼外沿中点居中，一格一像素输出透明底 PNG，以 data URL 写入 `avatars.generated.ts`（约 20KB）。显示时 `image-rendering: pixelated` 最近邻放大，不做平滑。换图或重跑体素化后重跑脚本再构建。

## 数据来源

- 名册：Lead 会话的 `team/member`；任务：`team/task`，没有则用 Lead 的 `todo/write`。
- 交流：接收方日志里的 `agent-message`（成员消息）、`subagent-settled`（完工汇报）、子会话首条用户消息（招募）、Lead 的用户消息（你的指令）。
- 活动：`tool/call` / `tool/result` / `assistant/message`；已加载会话读内存，未加载的读持久化存储（按存储版本缓存）。
- 是否在跑：以浏览器会话状态为准，宿主推导（已加载且有未结束步骤）兜底。

## 角色

- 角色图鉴：点击角色进入细看（放大、自动旋转，可切正 / 斜侧 / 侧 / 背角度与站立、走路、打字、思考、等待、沟通、休息动作，← → 切换，Esc 返回）。
- 未知模型（兜帽旅人）的三视图由 `scripts/draw-unknown-persona.py` 绘制为 `assets/personas/other.png`，与其他各家同一规格、同一流程；`人设/体素/other.png` 存在时优先用它。`personas.ts` 的调色只给网格兜底角色用。
- 表情贴片的嘴色由各家肤色推算（暖褐粉），不用固定的红紫色。
- 快速档是缩小 0.8 的简装版（短发、短裙），刘海带黄色闪电发夹。
- 岗位：左臂袖章与胸章颜色、右手道具、工位摆设（后端服务器机箱、测试虫罐、审查稿纸…）；组长头顶金星、独立玻璃办公室。

## 自查

- 有三视图的厂商（`../人设/体素/<厂商>.png`）：`scripts/voxelize-personas.py` 按 DeepSeek 图的像素格（14px）切网格，生成 `src/office-scene/sprites.generated.ts`；`sprite-character.ts` 逐行推算截面（每段宽取正视图、深取侧视图的超椭圆，窄段按自身宽度收深度），按侧视图挖空；颜色按平滑法线分区（朝前取正视图、朝后取背视图、朝侧取侧视图），侧视图颜色只采用正 / 背视图附近出现过的（否则换成最接近的），头部前段侧面用相邻鬓发色。关节：头、上身、下身、左右腿（手臂未拆）。换图后重跑脚本再构建。
- 没有三视图的厂商（目前只有未知模型）回退到网格角色（`anime.ts`）。岗位道具与星标等小件是体素（`props.ts`）。

## 布局与动画

- 圆桌布局：组长坐圆心面朝前方，组员面朝圆心围一圈（前方 ±30° 留进出缺口，座位从后排往前排填；超过 8 人用前半圈的第二圈）。
- 像素画角色的头 / 上身 / 下身是一张蒙皮网格，三根骨骼驱动：脖子以上跟头；脖子以下的背后与两侧（长发所在）从髋到脖子逐渐过渡到跟头；胸前跟上身；髋部上下身平滑过渡。转头时长发顺着弯，不按颜色区分头发，任何角度都没有接缝。像素画角色转头幅度减半。另配可动手臂（肩宽按脸宽定、可用 `ARM_TWEAK` 逐家微调，前后只看肩膀那几行躯干的前沿；泡泡袖肩头往身体里接一段，颜色取立绘肩部袖色，手用脸部肤色）。
- 表情：`sprite-character.ts` 的 `FACE_SPEC` 手工标注每家正视图的眼睛 / 嘴位置，表情以贴片覆盖（闭眼、笑眼、半睁、张嘴、小嘴、微笑），`pose()` 按状态切换并自动眨眼。
- 动作：打字（命令行更快）、阅读、书写、托腮思考、抱臂等待（偶尔看表）、边说边比划、站立挥手、收到消息跳一下并惊讶。
- 摸鱼（`slack.ts`）：空闲的人在工位、沙发、站位上按人设轮换小动作，每 15 秒一段（做 11.5 秒、歇 3.5 秒，进出与休息姿势平滑混合），气泡显示动作名。各家专属动作：DeepSeek 干饭 / 吃饱趴睡 / 吐泡泡 / 「才不胖」跺脚；GLM 精读 Z 标笔记本 / 归档 / 偷笑吐槽 DeepSeek / 拉眼罩补觉；Kimi 吹长笛 / 托小星球 / 写朔月笔记 / 看月亮；GPT 写会议纪要 / 反复核对 / 没人时松口气；Claude 下午茶 / 读旧小说 / 望窗出神 / 提裙行礼；Gemini 逗猫棒 / 慌张念「好 AI」/ 洗脸 / 猫式伸懒腰；Grok 擦斧头 / 抡斧热身 / 喝「番茄汁」/ 跷二郎腿；千问摇折扇 / 叠千纸鹤 / 出神；兜帽旅人看地图 / 四处张望；另有通用的伸懒腰、喝咖啡；还有跟去处走的动作（`PLACES`，带 `place` 只在对应去处出现）：书架前找书 / 翻两页，窗边看窗外 / 哈气画画，盆栽旁浇水 / 数叶子，靠墙刷手机 / 打盹，空地闲聊 / 活动筋骨，茶几旁顺饼干，沙发打游戏 / 瘫着，工位偷刷手机 / 戴耳机听歌 / 摸零食 / 转椅子。轮换时不连着做同一个。道具是体素小件，挂在左手（`CharacterRig.hand`），抵消手臂旋转、始终正着拿；摸鱼时收起岗位道具。头顶可飘符号（Z、♪、○、?）。图鉴细看里有「工位摸鱼 / 沙发摸鱼 / 站着摸鱼」，可逐个指定动作预览。加动作：在 `ROUTINES` 里按人设写一段 `run`（在休息姿势上改关节，返回表情）。

## 加载

- 浏览器在按钮出现后空闲时预取场景脚本；脚本带 ETag，未重建时 304。
- 体素用整数键；工位几何按岗位缓存；休息区等装饰在首帧后空闲时再搭。

## 场景环境与信息

- 固定机位（`index.ts` 的 `fitOffice`）：办公室不能旋转 / 平移 / 缩放，镜头角度固定，按画布大小把房间（含墙厚、底座、墙顶上方留给头顶信息的空间）的包围盒投到画面里求外接框，居中并取能完整放下的缩放；画布尺寸变化时重算。轨道控制只在角色图鉴里启用。成员面板的「在场景中定位」不动镜头，只让选中光环放大闪几下。
- 房间 20×16（`ROOM`），后墙、左墙是整面墙（左墙靠前是大门，正对主过道），朝镜头的前墙、右墙按剖面图只留矮墙，底下一块地板底座，四周是天空。
- 休息区（`LOUNGE`）在后墙右侧、紧挨圆桌：沙发背靠后墙，坐着的人面朝镜头；站着喝咖啡的人只在茶几左右两侧；咖啡柜台在右后角，不挡人。书架移到左后角。
- 空闲去处（`IDLE_SPOTS` / `IDLE_PREF`）：停下的人不全挤在沙发周围，按人设挑一个没人占的地方——留在自己工位、沙发、茶几旁、书架前、后墙窗边（唯一背对镜头的点）、靠左墙、右侧空地（两人面对面聊）、右前角盆栽旁。偏好：DeepSeek / Grok 沙发，GLM 书架，Kimi / Claude 窗边，千问盆栽，Gemini 空地，GPT 工位，兜帽旅人靠墙；偏好的都被占了就按 `IDLE_SPOTS` 顺序找空位，再没有就留在工位。组长仍去自己的休息点。
- 闲逛（`wander`）：空闲且已到位的人每 40～90 秒换一个没人占的去处（含回自己工位），偏爱的去处权重 3、其余 1；组长、有提醒的人不闲逛。
- 寻路（`nav.ts`）：房间划成 0.25 的格子，工位、沙发、茶几、柜台、书架、盆栽、落地灯的水平包围盒按人的半径外扩成障碍（贴地的地毯不算），8 邻域 A*（不许斜擦墙角）后按视线拉直成少量拐点。座位在家具包围盒里，用「入口点」进出：椅子从椅背一侧、沙发从正前方，站位就是本身（都再就近挪到空地）。路线 = 出座位到入口 → A* → 走进目标座位；目标一变就从当前位置重新寻路（走到一半也会掉头）；工位增减、陈设搭好时重建格子并让正在走的人重新规划；寻不到路时退回预设路线。行走起步加速、到站减速；互相靠近时往旁边（统一偏右）让一点，让完仍在空地上才挪。
- 环境按本地时间切换（`environment.ts`）：早晨（5–10 点）、正午（10–16:30）、傍晚（16:30–19:30）、夜晚，四周天空（容器背景，夜里有星星）、阳光（月光）方向与颜色、窗外景色（天空 + 城市剪影的画，傍晚和夜里亮灯）随之变化（每分钟检查）。傍晚起开灯：后墙、左墙的壁灯与沙发旁落地灯亮起并带光晕，三个室内点光源加暖色半球光把房间照亮。
- 醒目提醒（与浏览器桌面通知 `TurnNotify` 同一类时机，但在办公室里看得见）：快照里每个成员带 `lastTurn`（最近一轮结束的时间、是否成功；之后又开了新一轮就没有）。当组长这一轮已结束、之后你没再发过指令、整个团队都停下来（还有人在干活时组长会被汇报自动叫醒，不打扰你）、且这次还没看过，持续 2 秒后：组长走到桌前面朝镜头频繁挥手、蹦一下（出错时低头垂手），头顶浮一个不被遮挡的大「!」（汇报为金色、出错为红色，带描边与光晕），脚下光圈扩散；HUD 顶部弹出横幅「组长汇报完毕，在等你回复」/「组长这一轮出错停下了」，可「查看汇报」（打开组长对话）或关掉；左栏组长动态同步显示。打开组长对话、关掉横幅、或对话本来就开着组长会话，都记为已看过（按组长记在 localStorage `dsh-config:office-ack`，刷新后仍记得）。
- 未读红点：只看组长（组员只和组长交互，你只需关注组长的汇报）。组长最近一轮结束（说完一段话）晚于你上次打开他的对话，左栏「组长动态」的对话按钮就亮红点；组长有醒目提醒时也算未读。成员卡上不显示未读，「队伍」标题旁也没有未读计数。localStorage `dsh-config:office-reads` 存 `{ v: 2, leads }`，按组长会话 id 记 `{ seen, latest }`：latest 是见过的最近一轮结束时间（新开一轮后快照里没有 `lastTurn`，所以自己记住），打开组长对话、或对话正开着组长时把 seen 拉到 latest；第一次见到某个组长以当时为基线，旧消息不算未读。旧格式（每个成员一条）直接忽略。
- 角色头顶的名牌与气泡只在鼠标悬停或选中时显示（离开后保留 0.6 秒，方便点名牌）。墙上不再挂待办白板（左栏「组长动态」里有）。
- 信件飞行时每帧追踪收件人当前位置，人走开了也能送到。
- 手动换模型（`src/office/member-model.ts`）：原生模型选择器对子智能体会话整体禁用，宿主的 `selectModel` 也拒绝子智能体拥有的会话（还会把选择存成默认模型）。成员详情的「模型」区块从 `GET /dsh-config/office/models` 读全部供应商的模型（可搜索，按供应商分组），选中后 `POST /dsh-config/office/model` 直接对成员的 Agent 记一条 `model/selection`（不改默认模型，先用 `llm.resolveCallConfig` 预检）；「推理」下拉列该模型的推理强度（`?provider=&model=` 查询），「默认」即不带强度。记录的选择优先于创建时的 `agentOptions`，下一步起生效（正在进行的这一步不变），续跑沿用。成员没加载时（dsh 重启后组长还没恢复它）返回 409。快照里成员的模型在新选择被请求用上之前优先显示新选择，另带 `reasoningEffort`。
